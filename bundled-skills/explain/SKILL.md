Explain the code the user points to (or the current selection/file if none specified).

- **What it does**: one-paragraph plain-English summary.
- **How it works**: walk through the key steps or data flow in order.
- **Why it is written this way**: call out non-obvious design choices, constraints, or trade-offs.
- **Gotchas**: edge cases, side-effects, or common misuse patterns a reader should know.

Keep the tone direct. Assume the reader is a competent developer but may be new to this codebase.
